## Evidence and research semantics

The active pages consume `src/api/isemotalk.ts`, whose confidence contract is 0–1. Display formatting rejects nonfinite or out-of-range scores rather than showing `NaN%` or a value such as `8200%`. A model score is explicitly distinguished from validated accuracy.

The review screen preserves original predictions alongside QA confirmation/correction. When transcript or speaker changes affect the original inputs, the screen explains that the model was not rerun and can show the original transcript and speaker. New backend `predictionInputChanged`, `originalText`, and `originalSpeaker` fields are optional for compatibility with older records. Speaker edits can also affect stereo channel selection, so this warning covers both kinds of change.

Acoustic, lexical, and fused outputs are shown only when supplied. In particular, the frontend does not invent unimodal predictions for a fused-only checkpoint. Missing outputs remain “Chưa có đầu ra”. Per-stage provenance, adapter/model identity, verification flag, and measured duration are displayed only when the backend records them. The upload panel distinguishes configured from loaded ASR using optional `loaded` metadata.

Moments are described as rule-based suggestions for human review. If backend evidence for a previously reviewed moment becomes outdated, `reviewOutdated` produces a visible reminder to recheck it. Analytics explains the customer-only denominator, unknown-speaker exclusions, and that final emotion uses QA corrections where supplied and otherwise the model prediction. Review completion, inference readiness, and business resolution remain separate.

The root-owned `CallWorkflowPanel` is integrated after the transcript/review grid. It has its own endpoint and version; this frontend task did not implement or change its business rules.

## Draft and concurrency behavior

`src/lib/reviewSession.ts` handles snapshot creation, sparse payloads, serialization, validation, and recovery. Only changed fields are stored, avoiding duplication of a complete private transcript when only a note changes. The original backend version is retained.

- Same call and version: restore unsaved transcript, speaker, labels, notes, moment relevance, and completion changes.
- Different version or missing utterance/moment identity: keep the draft separate and present download/discard choices. No automatic rebase overwrites another tab's work.
- Invalid draft: preserve its raw content for recovery rather than applying untrusted or malformed state.
- Save conflict: retain the draft, explain the conflict, and allow downloading it before opening the new saved version.
- Successful save after navigation: remove only the exact snapshot the request saved; do not remove a newer draft for that call.
- Unavailable browser storage: show a visible warning, retain full-page unload protection, and guard link navigation. Saving to the server or downloading the draft remains the reliable recovery path.

Session storage is scoped to the browser tab/session, not a durable cross-device backup. Draft downloads are recovery files for inspection; no general draft-import/merge UI is claimed.

## Audit limits and follow-up

1. This task performed source review, helper/API tests, and production builds. It did not itself inspect live browser screenshots or run a DOM testing framework. Root-owned integration QA must confirm desktop/narrow layouts, native audio seeking, delayed saves, refresh/navigation draft restoration, and hidden-file mode switching in the actual served application.
2. The transcript still renders all rows on first load. Memoization removes repeated row rendering during clock updates; it does not provide virtualization for extremely long recordings. Add windowing only after measuring an actual long-call browser bottleneck.
3. Network requests can remain pending if the transport never settles; serialized polling prevents overlap, but it is not a request timeout or an offline queue. The UI cannot guarantee completion if its local services stop.
4. Session storage can be disabled, cleared, or exhausted by the browser. The UI reports failure and provides explicit server save/draft download. It does not claim persistent recovery after the browser session is destroyed.
5. Legacy `src/components/ui/*` business components, `src/types/index.ts`, and `src/data/mockData.ts` are not imported by active routes. Their obsolete 0–100 confidence assumptions, fake interval audio player, mixed timestamp units, and some mojibake remain dormant. They were not reused, silently rewritten, or deleted in this bounded change; a separate archive/removal cleanup would reduce future confusion.
6. The browser displays evidence recorded by the backend. Neither this audit nor passing workflow tests establishes SER accuracy, ASR accuracy, genuine model restoration, contact-center validity, or production security.

## Independent-review follow-up — 17:30 UTC

The independent reviewer found an inherited QA integrity problem: transition moments contain `[previous, current]` supporting utterances, but playback starts at `current.start`. The old click handler opened the first (previous) sentence in the editor while seeking the current one. `getMomentTarget` now chooses the transition's current anchor when it contains the playback timestamp, retains the first supporting sentence for sustained runs, and otherwise uses supporting evidence at the timestamp. Identical start times and overlapping intervals are covered; unrelated utterances are never selected. The page consumes the returned editor ID and seek time together.

Seven selection tests cover escalation, recovery, high-confidence change, overlap, identical start times, sustained runs, and missing/unrelated evidence. The old selection behavior failed the appropriate assertions before the fix; all seven now pass.

The reviewer also identified that useful row-level import errors in `response.details` were discarded. API errors now retain at most three nonempty string details, each capped at 240 characters, while ignoring objects and preserving HTTP status/error code. The upload alert renders these details as separate lines. Two new regressions were observed failing before this change and passing afterward.
