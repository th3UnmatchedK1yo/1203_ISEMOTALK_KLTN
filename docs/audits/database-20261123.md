# Database integrity audit — 2026-11-23

Baseline: `b836f7a3d596642c8e562b242cdd55b740451955`, branch `feat/thesis-demo-hardening-20261122`. Scope: actual SQLite schema, repository queries, QA/workflow transactions, file deletion, migrations and read-only diagnostics. Fixtures were in-memory or isolated temporary directories. The Windows user's database/recordings were not inspected, migrated or deleted.

## Findings and implemented changes

| Finding | Reproduction / implication | Resolution |
|---|---|---|
| Literal backslashes broke search | Titles such as `C:\work` did not match; `\%`/`\_` changed LIKE semantics | Escape backslash, percent and underscore while retaining bound parameters |
| Workflow history omitted business fields | After two valid saves, old ticket/contact/queue/reason values no longer existed | New events contain complete normalized `snapshot`, format version 2; old stored JSON is untouched and returned as `legacy_partial` |
| Most domain validation existed only in API | Direct SQL accepted invalid enum/range/interval/JSON/prediction values and duplicate utterance order | Shared contract: native CHECK for new tables, additive INSERT/UPDATE guards for legacy tables, unique `(call_id,idx)` |
| Nullable TEXT primary keys | Legacy `calls` allowed direct NULL primary-key inserts | Explicit NOT NULL on fresh tables and NULL-aware identity guards on migrated tables |
| Schema initialization was ad hoc | Workflow DDL depended on attaching HTTP routes | Centralized database opening and atomic migration journal, schema version 1 |
| Filesystem failure followed committed relational deletion | Injected EACCES returned 500 even though call/children were already gone; audio retained, retry 404 | Durable audio cleanup intent committed with delete; physical removal attempted afterward and retried at startup |
| Legacy audio reference could target a sibling directory | Controlled `../audit-sibling/audio.wav` reference made old DELETE remove outside uploads | Validate own call directory and link resolution before delete/cancel; reject unsafe references with 409 |
| Initial diagnostic/migration missed a dropped non-domain column | Independent reviewer removed `calls.audio_name`: old diagnostic said healthy while next insert failed | Complete required-column inventory; reopening/checker reject missing columns |
| Index-name collision defeated first migration's uniqueness | Existing nonunique `idx_utterances_call_order ON utterances(text)` masked new unique index | Verify actual unique key after installation and before migration stamp; collision rolls back complete schema transaction |

The direct-SQL findings demonstrate missing persistence guarantees at baseline. They are not claims that ordinary validated API requests were creating those invalid values. Invalid legacy paths were introduced only in disposable fixtures; no normal upload endpoint was found that lets a caller set `audio_file` arbitrarily.

## Guarantees established by tests

- Invalid INSERT/UPDATE statements fail on fresh schema; migrated legacy tables receive equivalent guards.
- Valid legacy calls, utterances, workflow event bytes, notes and ID continuity survive migration/reopen; missing evidence column is added without rewriting records.
- Malformed legacy JSON, duplicate order, orphan rows, missing FK declarations, missing required columns, incompatible future versions and index collisions do not become silently accepted current schemas.
- Failed migrations roll back schema/row changes. Independent index-collision reproduction compared `sqlite_master` definitions before and after rollback.
- Foreign keys reject orphans; deleting a call cascades relational children while the intentionally independent cleanup intent survives.
- Failed workflow event insertion rolls back form, version and event history together.
- Cleanup queue insertion failure rolls back delete; filesystem failure retains the job and logical-delete success; app startup retries; stale jobs never delete a live call's recording.
- Traversal, root/sibling ownership and external symlink/junction cases are rejected. Removal of an owned directory containing a child link leaves its external target intact.
- Checker opens read-only, never creates a missing database, never migrates/cleans, and distinguishes schema/structural/FK/domain/file issues. Closed-file checks leave DB bytes unchanged.
- A stopped-service full-directory copy can be reopened with matching call/workflow rows and recording bytes.

## Documented limits

This is a single-host, single-API local application. There is no multi-process job lease, authenticated reviewer identity, immutable annotation audit, normalized CRM master data or per-run model-package digest registry. Workflow JSON/current summary columns are documented physical-design tradeoffs, not a blanket 3NF claim. Checker does not recalculate every derived aggregate or prove consistency of every nested JSON business field.

Database and filesystem operations are not one atomic transaction. Audio cleanup can remain pending; HTTP 204 confirms relational deletion. Tests simulate lock/permission errors and restart behavior; they do not establish actual Windows hardware/file-lock behavior or secure erasure. User DB migration, actual model memory/latency, SER accuracy and projector readability still require the deployment machine and appropriate labeled data.
