# Backend audit and hardening — 2026-11-22

Baseline: PR #5, commit `9f7ced37d7ddbf253bc7946c111662bc8732e785`. Implementation branch: `feat/thesis-demo-hardening-20261122`.

## Scope and conclusion

The audit covered every file in `server/src`, the existing API/domain/client tests, and the Node-to-FastAPI boundary. The Express/SQLite architecture remains suitable for the documented local, single-user, post-call demonstration. The changes below strengthen data integrity and traceability; they do not restore a research model, establish contact-center accuracy, or demonstrate production throughput.

PR #5's unknown-speaker handling and `agent_channel` forwarding were already present and covered. They were retained. The new work addresses separate defects.

## Findings and implemented changes

| P1 | `MAX(existing ID) + 1` reused a deleted call's identifier. A delayed ASR result could overwrite a replacement call's transcript and fail its processing. | Persistent `id_counters` allocation survives deletion and database reopen. Deletion aborts the active HTTP wait, removes queued work and invalidates late writes. Tests cover a delayed ASR result, deletion, a replacement call, cancellation and subsequent queue progress. |
| P1 | A stage wrote output before its completion checkpoint. ## Additive data contracts

### Utterance

Existing fields are unchanged. Responses add:

```ts
originalText: string
originalSpeaker: 'agent' | 'customer' | 'unknown'
predictionInputChanged: boolean
```

The last field is true when a stored fused prediction exists and the current text or speaker differs from the inputs used for that prediction. Speaker changes matter because stereo channel selection can depend on the role. The server does not claim that editing these fields reran the model.

### Stage evidence

`StageEntry` adds optional `durationMs`, `provenance`, and:

```ts
evidence?: {
  adapter: string
  model?: string
  device?: string
  mock: boolean
  verified?: boolean
}
```

Evidence is persisted only when returned by the component that performed that stage. Current health is never used to invent evidence for an earlier run. Missing evidence in old records remains missing. Elapsed stage time includes request and persistence work and is not a model benchmark.

### Moment review and coverage

`MomentDto.reviewOutdated` marks an old verdict whose supporting evidence changed. Current `relevance`/`note` are then empty, while raw historical records remain available in the audit export.

Analytics adds `coverage` with `customerUtterances`, `customerWithEmotion`, `unknownSpeakerUtterances`, `unpredictedUtterances`, and `callsWithCustomerEmotion`, computed over ready calls.

The existing `priority` counts gain `unknown`; ready calls without a customer dominant emotion contribute there instead of `low`. The compatible stored `priority` fallback on an individual call is interpreted together with `dominantEmotion` and is not a customer-risk assessment when that field is null.

### Local origins

`ISEMO_ALLOWED_ORIGINS` is an optional comma-separated list of exact additional origins. It extends the default HTTP loopback origins. It is not authentication and should not be treated as a production access-control system.

## Rulings and remaining limits

1. **Confidence is required for imported predictions.** Previously accepted files that omitted scores must now provide them. Fabricating a perfect score would contaminate both displayed confidence and heuristic moment detection.
2. **Human edits preserve model evidence.** The application exposes changed inputs and retains original model outputs. Automatic reruns are deferred until genuine model versioning, review invalidation and compute cost are explicitly handled.
3. **JSON export is an audit snapshot, not a database restore format.** Re-import remains a precomputed-results import and deliberately labels the new record `imported`; it does not silently restore reviewer identity or operational history. Preserve the SQLite database and recording directory for full operational backup.
4. **Cancellation is cooperative at the HTTP boundary.** It aborts the Node wait and blocks late persistence. An already running synchronous Python model call may still finish; this is not a hard GPU/CPU cancellation guarantee.
5. **The pipeline remains one local worker.** It has no distributed leases or multi-process processing guarantees. Deploy only one API/pipeline instance against a database in this demo architecture.
6. **Analytics/export still use synchronous SQLite and in-memory aggregation.** The added coverage counts do not establish scalability. Large call collections need measured pagination/aggregation/background-export work before production claims.
7. **No neural model was restored by this backend work.** `real` denotes the service's actual computational source, while `verified` is preserved only when supplied as model-package evidence. Neither field establishes call-center accuracy or business resolution.
8. **Development seed/reset remains a development operation.** Seeded audio is synthetic and every seeded call remains mock-labeled. Avoid reset for a database containing reviewer work; this batch does not redesign that utility.
