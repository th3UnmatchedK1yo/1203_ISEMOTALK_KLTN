Launcher dùng `concurrently` đã có trong lockfile, không thêm dependency. API chương trình của phiên bản 10 dùng `killOthersOn`; cấu hình dừng cả khi child exit code 0 lẫn khác 0. Trên POSIX, shell exec trực tiếp nội dung lệnh foreground của các script đã có; bỏ lớp npm trung gian để giữ PID cho escalation. Các script demo POSIX phải là lệnh node/vite đơn, không phải chuỗi shell operators. Fallback 15 giây dài hơn cửa sổ drain 10 giây của API. Backend `tree-kill` trên Windows dùng `taskkill /T /F`, vì vậy timeout này không bảo đảm graceful shutdown trên Windows. Một tiến trình lạ chiếm cổng sẽ không bị launcher tự dừng. Probe cổng không loại bỏ được race sau khi kiểm tra; nếu có tiến trình khác chiếm cổng ngay sau đó, lỗi bind của dịch vụ vẫn làm cả nhóm dừng.

Không sửa model selection, `inference/.env`, cache hoặc dữ liệu đã lưu. Không tải model, tạo lại venv hoặc thay stack. `ISEMO_AUTO_SEED` mặc định 0 riêng trong launcher; giá trị được người dùng đặt rõ vẫn được giữ.

## Kiểm chứng trong môi trường phát triển

### Tái hiện trước khi sửa

- CLI readiness cũ trả 0 khi web đã dừng dù có build và API/inference khỏe.
- Các test trước sửa cũng ghi nhận false positive với HTML khác ứng dụng, build cũ, thiếu JavaScript, proxy hỏng, thiếu dist và inference trực tiếp không truy cập được.
- Python wrapper cũ giữ exit code của child nhưng thiếu interpreter/PID/exit diagnostics; đường dẫn override tương đối dẫn tới lỗi khó hiểu do khác working directory.

Các số này kiểm tra hành vi phần mềm. Chúng không đo accuracy, ASR/SER latency, CUDA, thao tác audio trong trình duyệt, hoặc độ ổn định của Windows laptop. Job Windows chạy Node 22; kết quả từng lần ở GitHub Actions. Native Ctrl+C, terminal integration và nguyên nhân kết thúc gốc trên máy người dùng vẫn cần log tại máy đó.

### Review độc lập và xử lý

Review read-only trên toàn bộ thay đổi startup/tài liệu tìm bốn vấn đề Important. Cả bốn được tái hiện bằng test trước khi sửa:

1. Npm/shell trung gian thoát trước worker chống TERM làm force-kill mất PID, launcher treo quá 19 giây. Đã đổi POSIX sang exec foreground, giữ Windows backend; test launcher thực với listener thật qua.
2. HTML bị sửa hoặc JavaScript bị thay nhưng giữ nguyên tên file vẫn qua check. Đã so sánh SHA-256 trên bytes thực tế của HTML và entry assets; test UTF-8 và từng trường hợp lỗi qua.
3. Bundle đã build với `VITE_API_BASE_URL` khác vẫn được kiểm tra qua proxy local. Đã thêm metadata từ Vite resolved environment, buộc same-origin cho demo local và giữ override khi chạy deployment riêng.
4. API qua web proxy báo mất inference nhưng API trực tiếp khỏe vẫn qua check. Đã kiểm tra reachability ở cả hai đường và ghi rõ đường hỏng.

Hai nhận xét về mô tả đã được chỉnh: Windows có thể force-stop ngay, và chỉ preflight/cache-only faster-whisper warmup bảo đảm không tải model; job được resume theo adapter tùy chọn có thể cần mạng. Không có thay đổi model hoặc thử nghiệm nghiệp vụ mới từ review này.

Các phần review chưa thể kết luận vẫn được giữ là giới hạn: tác nhân Windows gốc, interactive Ctrl+C, thao tác React/audio, accuracy/latency model thật, GPU fit, tái lập độc lập paper private và khôi phục sau power loss. Không lấy test phần mềm để kết luận các mục này.

## Các quyết định và giới hạn còn lại

- Giữ stack hiện tại: sửa lifecycle/diagnostics phù hợp lỗi quan sát được; viết lại Rust chưa có số đo chứng minh lợi ích cho đường suy luận này.
- Giữ mô hình triển khai cùng máy: API hiện gửi đường dẫn audio, vì vậy chuyển worker sang máy khác cần thiết kế transport trước.
- Dùng một lệnh foreground, không thêm service tự chạy nền/auto-restart. Nếu có lỗi, dừng có log giúp thấy lỗi thật; mở lại terminal không tự phục hồi tiến trình đã bị OS buộc dừng.
- Giữ backend quản lý tiến trình đa nền tảng đã có; không thêm giao thức shutdown riêng trong đợt sửa này. Hệ quả là Windows có thể dừng cưỡng bức cây tiến trình; không tuyên bố đã bảo đảm drain mọi công việc đang chạy trên Windows.
- Không nhận mình đã tái hiện chính xác tác động của VS Code hoặc terminal Windows. Cách thu log và kiểm tra listener nằm trong [runbook](../DEMO_RUNBOOK.md).
- Full SER từ raw audio, model/package identity theo từng run và benchmark miền tổng đài là những việc độc lập còn cần hoàn thiện, đã được chỉ rõ trong [kiến trúc nghiệp vụ](../BUSINESS_ARCHITECTURE.md).

## Tự kiểm tra trên laptop

Sau khi pull cùng nhánh và build, chạy `npm run demo` trong PowerShell riêng; giữ cửa sổ mở. Từ terminal thứ hai chạy `npm run demo:check -- --warmup-asr`. Nếu launcher tự thoát, giữ log dịch vụ/exit code và danh sách listener theo runbook. Đây là dữ liệu cần để xác định tác nhân Windows còn thiếu; chưa cần thay model hoặc cài lại toàn bộ môi trường.
